# pcb_solve_v2 性能等价加速设计（408 components / 154 edges）

## 1. 目标与约束

- 目标：在不改变默认算法语义与结果质量前提下，将 `pcb_solve_v2` 端到端耗时压到 **<= 60s**（同一输入规模）。
- 范围：仅 `pcb_solve_v2` 主链路（preA/phaseA/B/C），不含 `topology_viz`。
- 质量硬门槛（必须同时满足）：
  - PhaseC 成功边数不下降
  - DRC 违规数不增加
  - 总线长度/线段数不变差

## 2. 方案比较与结论

### 方案 A：工程侧优化（并行/日志/IO）
- 优点：风险最低。
- 缺点：对核心热点帮助有限，难稳定达到 <=60s。

### 方案 B：算法等价加速（推荐，已确认）
- 优点：不改决策语义，直接命中热点。
- 缺点：实现复杂度中等，需要严谨失效策略。

### 方案 C：激进剪枝/近似启发
- 优点：潜在收益最高。
- 缺点：质量退化风险高，不满足本轮“默认路径不退化”要求。

结论：采用 **方案 B**。

## 3. 设计

### 3.1 热点 1：floating_placer 全量重算 -> 增量 delta 评估

- 现状问题：SA 每次扰动后全量重算交叉/重叠/距离类代价，复杂度接近 O(n²)。
- 设计：
  - 维护与组件相关的局部邻域索引（airwire/候选冲突对）。
  - 扰动时仅重算受影响组件及其邻接关系，得到 `delta_cost`。
  - 接受扰动后更新局部缓存；拒绝则丢弃临时变更。
- 语义保证：代价函数定义不变，仅计算路径由“全量”改“等价增量”。

### 3.2 热点 2：flex_drc 与几何冲突检测 -> 统一空间索引候选筛选

- 现状问题：线段相交、走线-焊盘、走线-器件体经常全对全比较。
- 设计：
  - 引入统一 AABB + 栅格桶索引。
  - 检测时先做桶内候选筛选，再进行精确几何判定。
  - 索引按阶段构建，局部变更触发局部桶失效。
- 语义保证：精确判定逻辑不变，仅减少无效候选对。

### 3.3 热点 3：skeleton_router 重复扫描 -> 缓存 + 失效更新

- 现状问题：rip-up/retry 过程中重复执行同构可达性与障碍扫描。
- 设计：
  - 缓存路径候选与通道可达性摘要（按 net/约束键）。
  - 障碍状态变更时按受影响区域失效，不做全量清空。
  - 保持原有 rip-up 策略与评分顺序不变。
- 语义保证：搜索空间与优先级不变，仅减少重复计算。
